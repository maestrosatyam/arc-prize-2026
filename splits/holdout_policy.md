# ARC-AGI-2 holdout policy (v1)

Manifest: `splits/arc2_eval_split_v1.json` (the file carries its own `manifest_sha256`).
Built by `scripts/arc2_build_splits.py` from the pinned ARC-AGI-2 clone
(`third_party/PINS.json`, sha `f3283f72…`) and a depth-1 clone of fchollet/ARC-AGI
(sha `399030444e0ab0cc8b4e199870fb20b863846f34`, cloned 2026-10-17).

## Layers

| split   | tasks | test outputs | purpose |
|---------|------:|-------------:|---------|
| dev     | 40    | 62           | debugging; unlimited runs |
| tune    | 40    | 53           | model / selector / controller choices |
| holdout | 40    | 52           | sealed; evaluated once after config freeze |

Assignment is deterministic: tasks ordered by `sha256(task_id + "arc2-split-v1")`, structural
groups (shared canonical train-input hash) kept together. In v1 all 120 evaluation tasks are in
singleton groups, so the split is the plain hash order cut at 40/40/40.

## Where labels live and who reads them

* Test outputs exist only under `eval/data/arc-agi_*-solutions.json` (generated by
  `scripts/arc2_build_eval_data.py`) and in the read-only upstream clone.
* `arc2/io/loader.py` strips every `output` under `test` before a `TaskView` exists; solver code
  receives `TaskView` only. `arc2/` must never import `eval/` or `splits/`
  (`arc2/__init__.py`).
* Holdout labels are read by exactly one code path: `eval/arc2_score.py` invoked from
  `scripts/arc2_eval_local.py`, which loads solutions only after `submission.json` has been
  written and sealed on disk.
* `scripts/arc2_eval_local.py --split holdout` refuses to run without `--confirm-holdout`; the
  run record of that single run is the holdout result of record.

## Rules for solver developers

1. Solver developers do not receive holdout task ids' solutions, per-output correctness on
   holdout, or holdout grids with labels. They receive aggregate numbers only (official score,
   pass@1, pass@2, shape accuracy, invalid rate, solved count) after the sealed run.
2. Selection, calibration and budget tuning use `dev` and `tune` only. Any experiment record whose
   `split_id` is `holdout` before the freeze is void.
3. The holdout is evaluated once per frozen candidate configuration. A second holdout run requires
   a new manifest version (`arc2_eval_split_v2.json`) with a documented reason; the v1 manifest is
   never edited.
4. Public ARC-AGI-2 evaluation tasks are public. Any pretrained checkpoint that may have seen them
   must be disclosed in the run record (`ckpt_hash` + note); the holdout then measures
   reproduction, not generalization, and the writeup must say so.

## Known contamination (recorded in `splits/arc2_training_overlap_v1.json`)

* 767 of the 1000 training tasks share an id with ARC-AGI-1 (766 identical as pair multisets,
  pair order shuffled upstream; `ac0c5833` has corrected cells). Solvers trained on ARC-AGI-1
  material are not "unseen" on these.
* 7 of the 120 evaluation tasks overlap ARC-AGI-1 (6 by id — `0934a4d8`, `136b0064`,
  `16b78196`, `981571dc`, `aa4ec2a5`, `da515329` — and `db695cfb` structurally equals ARC-AGI-1
  `55783887`). Report results with and without these when an ARC-AGI-1-trained component is used.
* 0 evaluation tasks structurally match a training task; 0 multi-member groups inside training.
